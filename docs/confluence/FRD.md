# Functional Requirements Document

## Purpose

Define what the enhanced Task Manager must do, derived from
[../jira/backlog.md](../jira/backlog.md).

## Functional requirements

| ID | Requirement | Source story |
|---|---|---|
| FR-1 | User can create a task with title, optional description, optional due date, and priority (default Medium). | baseline + TM-104, TM-105 |
| FR-2 | User can edit a task's title, description, due date, priority. | TM-101, TM-104, TM-105 |
| FR-3 | User can delete a task permanently, with confirmation. | TM-102 |
| FR-4 | User can change a task's status among To Do, In Progress, Done, in any direction (including reopening a Done task). | TM-103, TM-106 |
| FR-5 | User can search tasks by title substring, case-insensitive. | TM-107 |
| FR-6 | User can filter the visible list by status and/or priority, combinable with search. | TM-108 |
| FR-7 | User can sort the visible list by due date, priority, or created date, ascending or descending. | TM-109 |
| FR-8 | Overdue tasks (due date in the past, status not Done) are visually flagged. | TM-104 |
| FR-9 | API failures surface a user-facing error message rather than failing silently. | TM-TASK-009 |

## Out of scope (this release)

- Multi-user accounts / login / task ownership.
- Archive (soft-delete only excluded per [../human-review-log.md](../human-review-log.md); delete is hard-delete).
- Mobile/desktop native clients — web only.
