# High Level Design

## REST API surface

| Method | Path | Purpose | Story |
|---|---|---|---|
| GET | `/api/tasks?search=&status=&priority=&sortBy=&sortDir=` | List tasks with optional search/filter/sort | TM-107, TM-108, TM-109 |
| POST | `/api/tasks` | Create a task | baseline, TM-104, TM-105 |
| GET | `/api/tasks/:id` | Get one task | baseline |
| PUT | `/api/tasks/:id` | Edit a task (title/description/due date/priority/status) | TM-101, TM-104, TM-105 |
| PATCH | `/api/tasks/:id/status` | Change status (To Do / In Progress / Done), including reopen | TM-103, TM-106 |
| DELETE | `/api/tasks/:id` | Delete a task | TM-102 |

## Task entity

| Field | Type | Notes |
|---|---|---|
| id | integer, PK | autoincrement |
| title | text, required | non-empty |
| description | text, optional | |
| status | text enum | `todo` \| `in_progress` \| `done`, default `todo` |
| priority | text enum | `low` \| `medium` \| `high`, default `medium` |
| due_date | text (ISO date), optional | nullable |
| created_at | text (ISO datetime) | set on insert |
| updated_at | text (ISO datetime) | set on insert/update |

## Frontend screens

Single screen (see [wireframes.md](wireframes.md)): task list with inline
search/filter/sort controls, an add/edit form, and per-task action buttons
(Edit, Delete, status transitions).

## Error handling (TM-TASK-009)

All API errors return `{ "error": "<message>" }` with an appropriate 4xx/5xx
status. The frontend shows these as a dismissible toast rather than failing
silently, and retries are user-initiated (re-submit) rather than automatic.
