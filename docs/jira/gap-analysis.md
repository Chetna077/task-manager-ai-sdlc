# Gap Analysis — Baseline Task Manager

## Baseline application (v0.1)

A deliberately minimal task list app: create a task (title only) and mark it
complete. No editing, no deletion, no due dates/priority, no search, no tests,
no accessibility pass. This is the "existing functional application with
limited features" the capstone asks us to enhance.

## Identified gaps

| Gap | Impact | Proposed enhancement |
|---|---|---|
| Tasks can't be edited once created | Users must delete + recreate for a typo | Edit task (title/description) |
| No delete | List grows unbounded, no cleanup | Delete task |
| Completed tasks can't be un-completed | Mistaken "done" clicks are permanent | Reopen task |
| No due date | No way to track deadlines | Add `due_date` field |
| No priority | Can't triage what matters | Add `priority` enum (Low/Medium/High) |
| Binary complete flag only | Can't represent "in progress" | Replace boolean with `status` enum (To Do / In Progress / Done) |
| No search | Painful once list grows | Search by title |
| No filter | Can't narrow by status/priority | Filter by status and priority |
| No sort | List is creation-order only | Sort by due date, priority, or created date |
| No automated tests | Regressions ship silently | Gherkin scenarios + Playwright E2E + API tests |
| No accessibility/error-handling review | Poor UX under failure, unusable via keyboard | Accessibility pass, API error handling with user-facing messages |
