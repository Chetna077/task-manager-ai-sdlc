# Backlog

Formatted to paste directly into Jira (Epic → Stories → Tasks).

## EPIC TM-100 — Task Manager Enhancements

**Summary:** Bring the baseline Task Manager to a usable, testable release by
adding edit/delete/reopen, scheduling/prioritization, and search/filter/sort,
under an AI-assisted SDLC with human review at every phase.

**Scope decisions:** single-user, delete-only (no archive), web platform — see
[../human-review-log.md](../human-review-log.md).

---

### TM-101 — Edit an existing task
**Type:** Story · **Priority:** High
**Description:** As a user, I can edit a task's title and description after creation.
**Acceptance Criteria:**
- Given a task exists, when I edit its title/description and save, the change persists.
- Editing to an empty title is rejected with a validation message.

### TM-102 — Delete a task
**Type:** Story · **Priority:** High
**Description:** As a user, I can permanently delete a task I no longer need.
**Acceptance Criteria:**
- Given a task exists, when I delete it, it no longer appears in any list or search.
- Delete requires a confirmation step in the UI.

### TM-103 — Reopen a completed task
**Type:** Story · **Priority:** Medium
**Description:** As a user, I can move a "Done" task back to "To Do" or "In Progress".
**Acceptance Criteria:**
- Given a task with status Done, when I reopen it, its status changes and it reappears in active lists.

### TM-104 — Add due date to a task
**Type:** Story · **Priority:** Medium
**Description:** As a user, I can set/clear an optional due date on a task.
**Acceptance Criteria:**
- Due date is optional; invalid dates are rejected.
- Overdue tasks (past due date, not Done) are visually flagged.

### TM-105 — Add priority to a task
**Type:** Story · **Priority:** Medium
**Description:** As a user, I can set a task's priority to Low, Medium, or High.
**Acceptance Criteria:**
- Priority defaults to Medium if not specified.
- Priority is visible in the task list.

### TM-106 — Status workflow (To Do / In Progress / Done)
**Type:** Story · **Priority:** High
**Description:** Replace the boolean "complete" flag with a three-state status.
**Acceptance Criteria:**
- New tasks default to "To Do".
- Status can move freely between the three states (including reopen, TM-103).

### TM-107 — Search tasks by title
**Type:** Story · **Priority:** Medium
**Description:** As a user, I can search tasks by a title substring.
**Acceptance Criteria:**
- Search is case-insensitive and updates the list as I type.
- Empty search shows all tasks.

### TM-108 — Filter tasks by status and priority
**Type:** Story · **Priority:** Medium
**Description:** As a user, I can filter the task list by status and/or priority.
**Acceptance Criteria:**
- Filters can be combined with each other and with search.
- Clearing a filter restores the unfiltered list for that dimension.

### TM-109 — Sort tasks
**Type:** Story · **Priority:** Low
**Description:** As a user, I can sort the task list by due date, priority, or created date.
**Acceptance Criteria:**
- Sort order (asc/desc) is toggleable.
- Sort applies on top of any active search/filter.

### TM-TASK-008 — Testing
**Type:** Task · **Priority:** High
- Unit tests for validation and sorting/filtering
- API tests for CRUD/update/search
- E2E tests: create → edit → status change → search → delete

### TM-TASK-009 — Non-functional / UX
**Type:** Task · **Priority:** Medium
- Accessibility review (keyboard navigation, labels)
- Performance check for list rendering (pagination if needed)
- Error handling (API failures, retries, toast/messages)
